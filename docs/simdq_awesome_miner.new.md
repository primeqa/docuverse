## Why graph ANN beats the Threshold Algorithm on dense embeddings

On these dense granite embeddings the ranking is unambiguous: **HNSW ≫ exact brute force ≫ Fagin TA/TASD**. The decisive evidence is how each engine's per-query latency scales as the vector dimensionality grows from 384 → 768 (same corpus, N=225,669):

| engine | 384d ms/q | 768d ms/q | ×(→768d) | agree@K (768d) |
|---|---|---|---|---|
| HNSW (graph ANN) | 0.13 | 0.17 | **1.32×** | 0.9647 |
| exact brute force (FLAT) | 3.22 | 8.23 | 2.55× | 1.0000 |
| Fagin TA/TASD (best agree) | 1.55 | 8.08 | 5.20× | 0.9789 |

**HNSW is the whole frontier.** It runs ~25× faster than exact at 384d and ~48× faster at 768d for a fraction of a percent of nDCG loss (agreement 0.965). At this N and D it is a near-free lunch, not a trade-off.

**Why the scaling differs so sharply.** HNSW does a near-constant number of distance evaluations per query — an `ef`-bounded graph traversal of a few hundred to low-thousands of dot products, roughly independent of N. Doubling D only widens each of those few dot products, so its latency barely moves. It is the only engine whose cost decouples from the corpus size.

Fagin's Threshold Algorithm is the opposite. TA halts when the running threshold `T = Σ_d frontier_d` (the best still-unseen score, summed over dimensions) falls below the k-th best confirmed score. That collapses quickly only when the score is a sum over **few or sparse** attributes. Dense embeddings are the pathological case: every one of the 384/768 dimensions contributes a little, so `T` decays extremely slowly and a large fraction of the corpus survives sorted access to be fully scored by random access — each such scoring a scattered, cache-hostile gather. Both effects grow with D at once (slower threshold decay **and** wider gathers), so Fagin scales *worse than linearly* in D (5.2× from 384→768d, vs 2.6× for the linear-in-D exact scan).

The `epsilon` slack knob only attacks the random-access count, and slowly: on this data the sorted-scan depth floors at a few percent almost immediately, but even aggressive slack still fully scores a majority of the corpus. To reach HNSW's agreement Fagin must run *slower than exact brute force*; to reach HNSW's latency it must set epsilon so high that recall collapses. It is never on the Pareto frontier here.

**Takeaway.** For dense retrieval embeddings at this scale, use graph ANN (HNSW) or exact SIMD brute force. Coordinate-wise threshold pruning (Fagin TA) is a structural mismatch for dense vectors — it is built for sparse/few-attribute scoring — and these numbers are best read as a clean demonstration of *why* it loses, not as a competitive baseline.
